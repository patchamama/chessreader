Objective: a Studies library in the app (Database → Studies): import Lichess studies (one, a book made of linked parts, or everything of an author), keep them in the backend, list/sort/rate/delete them and open them in the reader as a book. Branch: main (work-unit commits + tag). Delivery: ask-on-risk. Runners: PHPUnit (apps/api), Vitest (apps/web); tsc + eslint last. Dev stack: web :5180, API :8090.

## Facts (verified by the parent)
- Lichess API (lichess-org/api specs): `GET /api/study/{id}.pgn` exports a study (public needs no token; headers per chapter: `StudyName`, `ChapterName`, `ChapterURL`, `Annotator` = `https://lichess.org/@/<handle>`, `UTCDate`…); `GET /api/study/by/{username}` streams ndjson with ONLY `{ id, name, createdAt, updatedAt }` (no likes, no owner, no description). The HTML study pages answer 403 to programs, so likes ("number of Lichess ratings") are NOT available: the app keeps a manual `lichessLikes` field the user can fill in. Rate limits: be sequential, ≥ 1.5 s between calls, honour 429 + Retry-After.
- The reader opens PGN books through the external book store (`useExternalBookStore`, `pgnToChapters` in features/gamesearch/pgnChapters.ts); Database games open that way (features/database/DatabasePage.tsx `open`).
- Lichess studies already in the commentary database (comments.sqlite, 9 studies) live as chapters in `comment_games` (PGN with `ChapterURL`/`StudyName`/`Annotator` tags, source kind 'lichess').

## Contract (API ⇄ web)
Study JSON: `{ id, name, author, chapters, games, comments, linkedIds: string[], groupId: string|null, partOrder: number|null, isBook: boolean, source: 'lichess'|'comments', updatedAt, importedAt, myRating: 1..5|null, lichessLikes: number|null }` (`author` = Lichess handle; `comments` = count of {comments}; `isBook` = it has linkedIds or belongs to a group).
Routes (JWT + approved, like the library routes; delete needs the owner or admin):
- `GET /api/studies?sort=name|author|rating|likes|updated|imported&dir=asc|desc&author=<handle>&q=<text>` → `{ studies: Study[], authors: { author, count }[] }`; default sort name asc; null ratings last in either direction.
- `GET /api/studies/{id}` → `{ study, pgn }` (the whole study PGN).
- `POST /api/studies/import { ref, follow?: boolean, depth?: number (default 3, max 6), max?: number (default 40, max 200), parts?: string[] }` → `{ imported: Study[], skipped: {id, reason}[], linked: string[], errors: {id, message}[] }`; `ref` is a study URL (with or without a chapter) or a bare id; idempotent (re-import updates the PGN, keeps rating/likes); with `follow` the links found in the chapters' comments (`lichess.org/study/<8 chars>[/<chapter>]`) are imported too, breadth first, cycle-safe, bounded by depth/max, all of them in one group whose root is `ref` (`groupId` = root id, `partOrder` = discovery order); `parts` adds explicit extra study ids to the same group (the Capablanca case).
- `GET /api/studies/lichess/user/{handle}` → `{ user, studies: { id, name, createdAt, updatedAt, imported: boolean }[] }` (from Lichess, public studies).
- `PUT /api/studies/{id} { myRating?: 1..5|null, lichessLikes?: int|null }` → `{ study }`.
- `DELETE /api/studies/{id}?group=1` → `{ deleted: n }` (`group=1` also deletes the parts of its group).
- `POST /api/studies/sync-comments` → `{ added: n, studies: n }`: creates `studies` rows (source 'comments') from the Lichess chapters of the commentary database so they are listed and openable too.
